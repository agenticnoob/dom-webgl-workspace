## 目标

把当前单一四面体 Hero 扩展为一个由滚动驱动的四章节个人主站。正四面体既是进入
页面时的视觉主体，也是四个章节的空间目录和章节之间的过渡装置：四个面稳定对应
四个章节，每个面显示对应章节画面的正三角形裁剪；滚动把选中的面送入屏幕并揭示
真实 DOM 章节，章节结束后再把画面收回四面体。

整站保持一个连续、可逆的滚动坐标系。视觉状态由实际滚动位置决定，不使用只能
单向触发或脱离滚动条继续播放的时间动画。

## 已确认的产品模型

- 页面共有四个章节，正四面体的四个面与章节一一对应。
- 初始画面展示完整四面体及四个章节面的视觉身份。
- 章节按固定顺序进入，不通过点击面自由跳转。
- 每个章节结束后先回到完整四面体，再转向下一个章节。
- 四面内容表达对应章节的首屏或核心画面，并按正三角形裁剪；不要求把完整长页面
  从头到尾压缩进一个面，也不要求任意 DOM 的逐像素无损实时截图。
- 章节内容达到正常网页比例后固定在屏幕中；正三角形边界继续放大，逐步带出此前
  被三角裁剪隐藏的内容。
- 三角形完全覆盖视口后，无感交接给真实 DOM，随后按普通网页方式浏览章节。
- 向上滚动时所有阶段严格反向执行，不允许跳段、重播或用独立动画补帧。
- 当前长按径向反色保留并升级为全站主题切换，只在完整四面体状态启用。

四章的内容职责、叙事顺序、过渡页信息角色、双语原则和最终 Hub 联系入口已在本文
后续章节确认。最终命名、正式文案、具体媒体、链接、排版和内部交互仍待后续设计，且
不得改变这里确定的空间叙事和滚动语义。

## 个人站定位与受众

这是一个以个人思想、实践和连接为核心的品牌型个人站，不是简历页、项目目录或单一
产品落地页。它需要依次回答：我是谁、我如何理解 AI 带来的变化、我实际构建了什么、
我正在向何处发出信号。

- 核心受众是互联网与 AI 行业中的从业者、研究者、创作者、独立开发者和潜在同道者。
- 第一认知目标是让访客理解站点作者是谁、做什么，以及其 Agent-first 理念。
- 项目与外部频道用于证明思想已经进入实践，不以堆叠技术栈、履历或账号数量为目标。
- 站点不以传统的 human-first 产品逻辑为唯一前提。未来构建的系统优先保证 Agent 能够
  发现、理解、操作和验证；人的直接可用性可以成为次要目标，但不能以此牺牲安全、
  责任、权限和可审计边界。
- Agent-first 的核心不是为 Agent 增加更多说明，而是降低其理解任务、选择工具、调用
  能力和验证结果的心智负担。

## 四章内容骨架

四章采用“自我 -> 公理 -> 构建 -> 联结”的认知路径。下列中英文名称是工作名称，
用于锁定内容职责，不是最终界面文案。

| 章节 | 工作名称 | 回答的问题 | 内容职责 | 主要内容形态 |
| --- | --- | --- | --- | --- |
| 1 | 自我 / Self | 我是谁，我做什么，我相信什么？ | 以抽象、克制的方式介绍个人定位、工作方式和核心理念 | 个人形象 GLB、短篇自述、少量身份与原则关键词 |
| 2 | 公理 / Axioms | 我如何理解 AI 与世界正在发生的变化？ | 展开 AI 的结构性影响、颠覆性、AI-native、Agent-first，以及长期讨论的 AI 与哲学问题 | 三至四个核心命题、简短论述、可选延伸文章 |
| 3 | 构建 / Builds | 这些思想如何进入真实实践？ | 展示当前项目及后续精选项目，说明问题、构建方式和 Agent-first 价值 | 项目案例、真实证据、GitHub 入口 |
| 4 | 联结 / Signals | 我正在创造和发布什么，如何继续同行？ | 汇集产品、内容品牌、视频账号和其他公开频道，形成面向外部世界的连接图 | 产品与频道入口、持续探索方向、章节结束语 |

### 第一章：自我 / Self

- 介绍个人身份、当前工作方向和核心理念，但不写成履历或具体个人资料表。
- 个人信息保持抽象，只表达独立构建者、AI-native、Agent-first、系统化实践等与站点
  叙事直接相关的身份坐标。
- 不默认展示年龄、所在地、教育、公司经历或其他不必要的具体信息。
- 个人形象 GLB 是本章的主要视觉锚点；语义自述仍由真实 DOM 承担，GLB 不替代文字
  身份和辅助技术可读信息。
- 本章结尾把“我是谁”引向“我为什么持续思考这些问题”。

### 第二章：公理 / Axioms

- 重点不是汇总 AI 新闻，而是呈现作者长期追问和可以持续修正的思想命题。
- 核心范围包括 AI 带来的结构性变化、AI 行业的颠覆性、AI-native、Agent-first、
  智能与理解、语言与认知、自动化与人的责任边界。
- 每个命题先提供一个清晰主张和最短必要论证；文章、视频或长内容只作为延伸入口。
- 不把推测包装成确定事实，也不把克制表达等同于没有立场。
- 本章结尾把思想命题引向真实构建：如果 Agent 成为软件的主要使用者，软件应如何改变。

### 第三章：构建 / Builds

- 当前 Viselora / DOM-first WebGL runtime 项目作为首个重点案例，后续只加入能够证明
  个人方向的精选项目，不追求完整 GitHub 仓库列表。
- 每个案例回答四件事：面对什么真实问题、构建了什么、Agent 如何使用或理解它、
  有什么可验证证据。
- GitHub 是案例的证据和深入入口，不用提交数量、语言占比或技术标签代替项目叙事。
- Agent-first 案例重点说明如何降低 Agent 的发现、理解、调用和验证成本，而不是简单
  宣称“支持 AI”。
- 本章结尾从“已经构建什么”转向“正在持续创造和发布什么”。

### 第四章：联结 / Signals

- 连接个人产品、AXMORF 或其他发展中的内容方向、博客、视频账号和后续公开频道。
- 这些入口按表达目的组织，不做成无差别社交账号列表。
- 产品、内容和频道可以在本章内交互；直接联系方式留到本章退出后的最终 Hub。
- 章节结束语采用用户确认的方向：

  > 愿与同道者共研同进，或有所得，亦未可知。

- 英文版本表达相同的开放与克制语义，不要求逐字直译。

## 整站路线

```text
初始完整四面体
  -> 章节 1 进入转场
  -> 章节 1 DOM 内容
  -> 章节 1 退出转场
  -> 完整四面体并转向章节 2
  -> 章节 2 进入转场
  -> 章节 2 DOM 内容
  -> 章节 2 退出转场
  -> 完整四面体并转向章节 3
  -> 章节 3 进入转场
  -> 章节 3 DOM 内容
  -> 章节 3 退出转场
  -> 完整四面体并转向章节 4
  -> 章节 4 进入转场
  -> 章节 4 DOM 内容
  -> 章节 4 退出转场
  -> 最终完整四面体或页面收束状态
```

章节之间的完整四面体状态是明确的叙事节点，不只是不可见的数学中间帧。每个该类
节点都允许用户看到四个章节面，并满足主题长按的启用条件。

第四章结束后的最终完整四面体不是普通的中间 Hub。它承担整站收束和直接联系入口，
具体规则见“最终 Hub 与联系方式”。

## 进入章节的转场

### 1. Hub：完整四面体

- 四面体以完整、可读的立体状态展示。
- 四个面保持稳定的章节身份和主题状态。
- 当前已实现的轻微呼吸、浮动和鼠标视差可以保留。
- 只有此阶段允许真实 mesh 长按触发全站主题切换。

### 2. Orient：目标面朝向镜头

- 当前滚动区间选择固定顺序中的下一个章节面。
- 四面体随滚动平滑旋转，使目标正三角面逐渐正对镜头。
- 旋转、位置和相机关系都必须由同一局部进度确定；反向滚动读取同一函数的反值。
- 本阶段不提前显示可交互 DOM。

### 章节门廊：四面体两侧信息

每次从 Hub 进入目标章节时，四面体两侧可以出现一组章节专属的简短信息。它们不是
独立页面，也不复述章节正文，而是在目标面靠近前建立语境。

- 两侧信息与当前章节 ID 稳定绑定；四次转场使用不同内容，但保持统一的信息层级和
  阅读节奏。
- 第一章使用身份坐标、工作方式和理念关键词。
- 第二章使用待回答的问题、思想命题或概念对。
- 第三章使用项目名称、构建原则、状态或验证信号。
- 第四章使用产品、内容品牌、视频频道和外部连接方向。
- 信息应短到可以在四面体仍完整可读时被理解，不形成两侧卡片墙或第二套章节导航。
- 当目标三角面靠近并扩大时，三角面在空间上逐步覆盖两侧信息；不依赖与滚动脱节的
  单向退场动画。向上滚动时，同一几何关系重新露出这些信息。
- 两侧信息如果承载真实含义，仍需保留可访问的 DOM 语义；三角遮挡效果由既有 WebGL
  合成关系承担，不新增 CSS mask、第二 canvas 或重复视觉真值。

### 3. Face-space approach：面空间靠近

- 目标面向镜头靠近并放大。
- 章节画面仍位于四面体面空间，跟随该面的透视、旋转和缩放。
- 章节矩形画面的可见部分由正三角面裁剪；面外内容仍被隐藏。
- 其他三个面随四面体整体离开主要视野，不创建第二个四面体或第二套状态。

### 4. Content lock：内容锁定

- 当章节画面达到真实 DOM 的目标比例、位置和响应式布局时，内容从面空间过渡到
  屏幕空间。
- 锁定完成后，章节内容停止缩放、旋转和位移，固定在视口中。
- 此时正三角形边界仍然位于屏幕内，用户仍能看见明确的三角裁剪轮廓。
- 锁定点前后的内容不得出现尺寸跳变、透视跳变或重新排版。

这一步是整个体验的核心：内容和三角边界从此拥有两个不同的运动规则。内容已经
成为固定网页画面，三角形继续承担揭示窗口。

### 5. Triangle reveal：三角窗口扩张

- 内容坐标保持完全不变。
- 正三角形裁剪边界继续随滚动向视口外扩张。
- 边界扩张持续揭示同一章节画面中此前被裁掉的区域。
- 不把三角形 morph 成矩形；矩形网页是被不断扩大的三角窗口逐渐揭示出来的。
- 裁剪、边缘抗锯齿和揭示必须由 WebGL 受控视觉路径完成，不使用 CSS
  `clip-path` 或第二张 canvas 绕过现有边界。

### 6. DOM handoff：真实章节接管

- 当三角窗口已经覆盖整个视口并带有足够 overscan 后，WebGL 画面与真实 DOM
  完成交接。
- 交接前后的章节比例、位置、主题和可见内容必须一致，不能出现闪烁或重新对齐。
- DOM 接管后才启用文本选择、链接、表单、焦点、辅助技术语义和章节内部交互。
- WebGL 章节画面始终是装饰性投影，不成为语义内容的第二来源。

## 正常章节与退出转场

DOM 接管后，章节按正常网页内容滚动。章节可以高于一个视口，内容长度由后续章节
设计决定，不需要为了四面体纹理把完整长页面压缩到一个三角面。

章节尾部设置独立退出区间：

1. 到达退出锚点后，章节当前退出构图固定在屏幕空间。
2. 三角窗口从视口外收回，逐渐裁掉章节画面。
3. 到达对应锁定点后，内容重新附着到四面体面空间。
4. 内容与目标面一起缩小、后退并恢复完整四面体。
5. 四面体进入下一个可见 Hub，再开始转向下一章节。

退出区间自身也必须完全可逆。从下一个 Hub 向上滚动时，应先反向展开上一章节的
退出构图，回到上一章节底部，再继续正常反向浏览章节内容。

进入章节与退出章节可以使用不同的页面构图锚点：进入对应章节首屏，退出对应章节
尾部画面。两者都必须保持“先锁定内容、再移动三角窗口”的同一空间语法。

## 最终 Hub 与联系方式

第四章完成退出转场后，页面回到最后一个完整四面体状态，以此完成整站收束。

- 直接联系方式分布在四面体周围，而不是塞入第四章正文或四面体面纹理。
- 第四章负责展示产品、内容与公共频道；最终 Hub 负责提供明确的直接联系动作。
- 联系入口只使用后续明确提供并允许公开的信息，不从个人资料或历史记录推断地址、
  账号或联系方式。
- 联系入口与真实 mesh 长按主题切换保持清晰的点击区域和交互优先级，不能让链接点击
  意外触发长按，也不能用页面级长按替代 mesh 命中。
- 最终 Hub 仍是滚动坐标的一部分。反向滚动时先撤回联系收束状态，再严格反向进入
  第四章退出构图。

## 滚动模型

### 单一滚动坐标

页面使用一条真实、连续的文档滚动轴。所有状态都可由绝对滚动位置重建：

```text
scroll position
  -> chapter index
  -> chapter phase
  -> local phase progress [0, 1]
  -> tetrahedron transform
  -> content-space mapping
  -> triangle coverage
  -> WebGL / DOM ownership
```

- 每一个视觉帧都必须对应滚动条上的确定位置。
- Lenis 只负责平滑输入和滚动位置收敛，不拥有独立叙事时间。
- GSAP/ScrollTrigger 或 progress store 只发布进度，不在 effect 外复制视觉状态。
- 不使用一次性进入事件、延时回调或不可逆的 committed scroll phase。
- 页面刷新、窗口 resize 或滚动方向改变后，应能从当前位置重新解析同一画面。

### 分段原则

每个章节至少拥有以下连续区间：

```text
hub -> orient -> face-approach -> content-lock -> triangle-reveal
    -> dom-content -> triangle-contract -> face-detach -> hub
```

具体滚动长度、pin 距离、缓动曲线和各阶段占比留到原型阶段通过真实视觉节奏确定，
但不得改变分段语义或双向可逆要求。

## 章节画面与纹理契约

### 内容身份

- 每个面持有稳定的章节 ID；滚动过程中不得交换面与章节的映射。
- 面内容需要让用户能识别对应章节，但允许为正三角构图调整裁剪焦点和视觉密度。
- 面内容与真实 DOM 使用同一章节数据和语义主题，不维护相互漂移的两份文案真值。
- 不要求把链接、按钮或表单在三角面阶段做成可交互元素。

### 双坐标空间

章节画面至少需要两个可连续混合的坐标表达：

- `face-space`：贴合三角面，随四面体运动；
- `screen-space`：与真实 DOM 视口构图对齐，不再随四面体缩放。

进入转场前半段推进两者之间的映射混合；到达 content lock 后映射固定为
`screen-space`，后续只更新三角覆盖范围。退出时按对应区间反向执行。

### 生成与更新

设计不强制使用通用 DOM 截图库。实现可以采用章节专用 Canvas 表达、受控纹理
图集，或后续确认的可复用 DOM-to-texture 能力，但必须满足：

- 主题切换、viewport resize 和章节内容变更后可重新生成；
- 不要求每帧重新栅格化静态 DOM；
- 图片、字体和纹理就绪前有稳定 fallback；
- 移动端使用受控纹理尺寸和 DPR，避免为四个面常驻超大纹理；
- WebGL 资源由 runtime/facade 管理并可完整释放。

## 全站主题切换

当前长按径向反色不是独立彩蛋，而是整站主题切换入口。

### 启用条件

- 仅当完整四面体处于 Hub 状态时允许开始长按。
- 初始 Hub 和章节之间的完整四面体 Hub 都满足该条件。
- orient、approach、lock、reveal、DOM 内容和 exit 阶段不响应主题长按。
- 交互源仍然是真实 tetrahedron mesh hit，不增加页面级长按捷径。

### 全局语义

- 已提交主题同时作用于背景、Ghost Cursor、四面体四个面和四个 DOM 章节。
- 四个面和 DOM 章节使用语义色角色，不各自硬编码互不关联的明暗色。
- 主题状态独立于滚动位置；向前或向后滚动都不自动反转主题。
- 径向动画只需要在当前可见 WebGL 画面中传播；隐藏章节在 commit 后同步到新的
  committed theme，后续进入时直接使用正确主题。
- 继续使用一份 app-owned committed theme 真值和现有 progress/signal 边界，不能
  为 DOM、纹理和 WebGL 分别创建可漂移的主题 store。

章节视觉设计必须同时验证 initial 与 inverted 两套主题，不能只在完成后自动反转
颜色并假设排版、对比度和图像都仍然成立。

## 现有架构承接

当前 `hero-next` 已具备可复用基础：

- 一个 `WebGLScrollRuntime`、一个 runtime 和一个 managed canvas；
- Lenis、GSAP、ScrollTrigger 和 progress store；
- 一个 managed perspective scene、camera、lights 和 `WebGLMesh` tetrahedron；
- app-owned scene-object effect 和受控 lit-material shader extension；
- 真实 mesh press、可逆 hold state machine 和全屏径向主题扩散；
- 稳定 effect declaration 与无 React per-frame state 的现有边界。

下一阶段应扩展 app-owned composition、scroll phase resolver、章节 surface 和
tetrahedron shader，而不是引入第二 renderer、第二 canvas 或 raw Three.js 所有权。

## 已知能力边界与实施前检查

以下能力不能从当前代码表面直接假定已经存在，实施前必须做 focused prototype：

1. 当前 public `WebGLMesh` 只声明一个 managed material，没有开箱即用的“四个面分别
   绑定四张章节纹理”声明。
2. 当前受控 shader uniform 支持 image/canvas texture，但需要验证稳定的面识别、
   三角 UV、纹理图集和 face-space 到 screen-space 映射路径。
3. 当前 `dom/element` renderable 不等于任意 DOM 子树的完整浏览器截图；若章节画面
   依赖 DOM 栅格化，需要明确新的受控输入与资源生命周期。
4. 当前 `apps/hero-next/AGENTS.md` 把 CSS 限制为 layout-only。真实 DOM 章节需要
   CSS/DOM 拥有语义排版、可访问颜色和主题 token，因此实施前必须显式更新 app-local
   边界：DOM/CSS 拥有语义内容和主题呈现，WebGL 继续拥有四面体、裁剪、shader、灯光
   和转场运动。

本设计不授权直接修改 `packages/`。如果 app 仅通过当前公开 facade 无法完成稳定的
面纹理或坐标映射，实施应先报告可复用的 public capability：声明形状、所有权、资源
生命周期、SSR 行为、dispose 和验证契约，再由用户单独授权 package 工作。

## 国际化：中文与英文

中文和英文是同一体验的两种语言表达，不建立两套章节结构、两条滚动时间线或两套
视觉状态。

- 两种语言使用相同的四章顺序、章节 ID、空间阶段、主题状态和最终 Hub。
- 章节名称、四面体面内容、章节门廊、真实 DOM、链接标签、页面 metadata 和可访问性
  文案都需要中文与英文版本。
- 英文不要求逐字翻译中文；两种语言应保持相同主张、语气、信息层级和行动含义。
- 中文和英文长度不同，最终排版必须分别验证标题换行、三角裁剪焦点、两侧信息密度、
  移动端可读性和 WebGL/DOM handoff 对齐，不能只验证一种语言后机械替换文本。
- 切换语言不改变当前章节语义、滚动方向或已提交主题；章节投影与真实 DOM 必须读取
  同一语言真值，不能出现四面体为一种语言而 DOM 为另一种语言。
- 在正式交付前，四章关键内容和主要链接不得只在一种语言中存在；无法等价翻译的品牌
  名称可以保持原文，但需提供必要的上下文解释。

## 响应式、无障碍与 Reduced Motion

- 桌面和移动端使用相同章节顺序与三角窗口语法，不为移动端建立第二套叙事状态。
- 章节画面按当前 viewport 生成或选择裁剪，不能把桌面截图简单压缩到移动端。
- 真实 DOM 始终是语义内容来源；纹理和 WebGL 投影对辅助技术隐藏。
- DOM 接管前不开放被纹理伪装的链接、按钮或表单交互。
- `prefers-reduced-motion` 下保留章节顺序、滚动位置和内容交接；关闭呼吸、浮动、
  shake 和非必要 pointer tilt。旋转距离、pin 长度和揭示速度的最终降级方式在原型
  验收时确定。
- 主题两端都必须满足正文、链接和交互控件的可读性与焦点可见性。

## 设计阶段非目标（历史）

- 本轮只确认四章内容职责和整体方向，不锁定最终文案、具体项目清单、账号地址、GLB
  资产、图片素材或章节内部排版。
- 本轮不实施四章扩展、国际化、个人 GLB、门廊信息或最终 Hub 联系入口。
- 不实现点击面自由导航、随机章节顺序或非线性路由。
- 不让三角面阶段承担真实 DOM 交互或无障碍语义。
- 不把完整长章节从头到尾压缩进一个三角纹理。
- 不把三角形几何 morph 成矩形网页。
- 不用 CSS `clip-path`、CSS mask、第二 canvas 或第二 renderer 绘制核心转场。
- 不增加 raw Three.js renderer、scene、camera、material、loader 或 render loop 所有权。
- 不把主题切换入口放进正常章节内容。
- 不在本设计文档中声明任何实现、自动化、浏览器验收、提交或发布已经完成。

## 设计验收标准

后续实现与视觉验收至少必须证明：

- 初始和章节间 Hub 能看到完整四面体，并识别四个稳定章节面；
- 四个章节严格按固定顺序进入，每章结束后都回到完整四面体；
- 四个章节分别承担自我、公理、构建与联结职责，不互相复制同一套泛化内容；
- 四次进入转场拥有各自的两侧门廊信息，三角面能够随滚动覆盖并在反向时重新露出；
- 面靠近时章节内容随 face-space 运动；到达锁定点后内容停止缩放和位移；
- 锁定时三角边界仍在视口内，随后只由边界扩张带出被裁剪内容；
- 三角覆盖视口后的 WebGL/DOM handoff 没有比例、位置、主题或像素级明显跳变；
- DOM 章节能够正常滚动、选择、聚焦和交互；
- 反向滚动逐帧恢复前一状态，并能从下一个 Hub 返回上一章节底部；
- 长按主题切换只在完整四面体 Hub 可用，并同步更新所有面和 DOM 章节；
- 中文和英文共享一套章节与滚动语义，且四面体投影、门廊和真实 DOM 语言一致；
- 第四章退出后回到带有直接联系入口的最终完整四面体，链接交互不干扰 mesh 长按；
- 全程只有一个 runtime、一个 canvas 和一份滚动/主题真值；
- desktop、mobile、reduced-motion 和两个主题都有明确浏览器证据，且不把自动化结果
  误报为主观视觉验收。
